# anvilkit-agent-mcp

The MCP service of the AnvilKit Agent platform (architecture V4.0, [DD-08](https://github.com/ancyloce/anvilkit-services/blob/main/docs/architecture/mcp.md), [DD-09](https://github.com/ancyloce/anvilkit-services/blob/main/docs/architecture/platform.md#async-config)). Go, grpc-go, Fx, pgx/sqlc, koanf, watermill, Casbin, the official MCP Go SDK.

The `anvilkit_mcp` schema is migrated by the parent repository's migration Job (`jobs/migration`, `internal/migrate/sql/mcp`, `00001` to `00009`); the binary embeds no migration, and a schema behind its minimum version (`MinimumSchemaVersion`, `internal/bootstrap/schema.go`) withholds readiness until the migration has run.

**Implemented (P14, durable background work):** the owner side of `anvilkit.mcp.v1.BackgroundTaskService` — `ClaimTask`, `HeartbeatTask`, `SubmitTaskResult`, `GetTask` — over the `background_requests`/`task_attempts` tables of migration `00002`, the transactional outbox of the pinned watermill-sql PostgreSQL adapter bound to the same `pgx.Tx` as every domain write, the in-process watermill forwarder to NATS JetStream, the lease sweeper with the Control original-dispatch query for external-effect leases, cancellation, the immutable configuration generations with secret rotation (a new pool built and probed off-path, then swapped, then the old one drained) and the bounded Fx lifecycle. The `local-check` task kind is the DEVELOPMENT_ONLY fixture of the background lane: the production schema admits only `mcp-catalog-refresh` (migration `00005`), and the development foundation's fixture set re-admits `local-check`.

**Implemented (P18, private catalog and grant barrier):** `CatalogService` and `GrantService` over migration `00003` (applied by `jobs/migration`). Discovery goes through the ContextForge connection layer (one gateway per canonical resource, refreshed on rediscovery; the negotiated protocol, the server identity and the live tools, resources and prompts are bound into a versioned, digest-identified descriptor, and a declaration that disagrees with the live server is `DESCRIPTOR_MISMATCH`). ContextForge's visibility, OAuth or UI never authorize anything: review is four-eyes (the discoverer never reviews), roles come from Casbin bindings per tenant (`catalog_manager`, `catalog_reviewer`, `grant_manager`; a reviewer is never a grant manager), and members see only approved or disabled revisions. A grant binds the revision's digest, protocol, resource, methods, selectors, data class, prices, cost cap and expiry into its policy digest; it is PENDING until Control's `GrantPolicyService` answers a receipt under the recorded command identity, and only ACTIVE with a receipt and an unexpired expiry is executable. A revocation stops new MCP admission when it commits (REVOKING), Control fences new tool admission, and REVOKED waits until Control reports no in-flight or unknown dispatch and no open MCP call; uncertain answers leave the barrier open for the reconciler (`barrier.*`). A changed server is a new revision under review; disabling a revision revokes its grants. 

**Implemented (P19, guarded tool execution):** `CallService` over migration `00004`. `CreateCall` validates the command, the execution binding and the exact argument bytes (digest, one JSON object without duplicate keys), checks the grant is executable for the caller's subject with the method granted and its descriptor revision still approved, the (resource, protocol, transport) combination is a reviewed qualified route (`calls.qualified_routes`, route `go-sdk`; everything else stays disabled, stdio is not qualified) and no UNKNOWN call of the server is open, then persists the call before anything else. Control's `AdmitTool` is asked under the call's own identity (the dispatch binds the argument digest and the effect class; paid reads and free writes alike); only the request that received `dispatchAllowed=true` may send. Before the send the connection is qualified — upstream authorization (the protected-resource metadata must still name the grant's resource and issuer, the authorization server's metadata its issuer, its token and JWKS endpoints must pass the network policy; client-credentials token with the resource indicator, cached per grant security dimensions), a session pinned to the grant's protocol version (the negotiated one must equal it), the live input schema digest of the method — and the send marker is committed with the grant still executable; exactly one `tools/call` follows over the official Go SDK with SSE reconnection and the standalone stream disabled, through MCP's guarded egress (reviewed hosts, every resolved and connected address checked, no redirects, no proxy, bounded bodies, bearer tokens only to their origin, inbound credentials never forwarded). Results are normalized to bounded typed data (text, binary reduced to type/size/digest, links kept as data, `untrusted: true`) with the private native evidence; usage is one call unit. A call admitted without a marker was never sent (CANCELED, zero usage); a JSON-RPC error the server sent is FAILED; anything else after the marker is UNKNOWN, never resent, and restricts new calls to the server (any call id) until Control's record of the original dispatch resolves it — no MCP server here has an original-outcome query, so that recovery is manual. The reconciler (`calls.reconcile_*`) repeats uncertain admissions and observations under the original identities.

**Implemented (P2.5, catalog refresh):** `CatalogRefreshService.AdvanceRefresh`, the claimant's step of the `mcp-catalog-refresh` background kind. On a schedule MCP requests one refresh per approved revision that an active grant can call; the Background Worker claims it and asks `AdvanceRefresh`, MCP re-reads the live server through its connection layer, rebuilds the descriptor from the reviewed declaration and records whether it still digests as the approved revision; acceptance of a drift disables the revision in the same transaction, so its grants begin revocation.

## Layout

- `cmd/anvilkit-agent-mcp` — the Fx entry point; `reconcile <callId>`, the operator entry point that asks Control for the original dispatch of an UNKNOWN call and settles it (it never sends upstream and needs no running replica); `local-check request|cancel|get`, built only under the `localcheck` build tag, are the DEVELOPMENT_ONLY owner entry points that create, cancel and read fixture requests through the same application code (no public create RPC exists).
- `internal/config` — koanf generations: defaults < `config.yaml` < validated Apollo snapshot < allowlisted `ANVILKIT_MCP_*` environment (`envOverrides` in `internal/config/config.go`); `database.url` (or `database.url_file`) is the only secret configuration value, and the ContextForge token, the upstream credentials and the NATS credential are read from the files their placements name.
- `internal/domain` — the request state machine (pending, leased, result_submitted, accepted, retry_scheduled, dead, stale, canceled), claim/heartbeat/submit/cancel/expire decisions, the event envelopes.
- `internal/application` — one transaction per command: decision under the row lock, attempt record, CAS update, outbox event; the lease sweeper; metrics.
- `internal/adapters/postgres` — pgx store and sqlc queries (`sqlc.yaml`, `tools/sqlc.sh --check`); `internal/adapters/outbox` — the watermill-sql publisher on the transaction and the forwarder; `internal/adapters/control` — the `GetDispatch` query and the `GrantPolicyService` client; `internal/adapters/contextforge` — the ContextForge client (gateways, handshake, listings; token read from `ANVILKIT_MCP_CONTEXTFORGE_TOKEN_FILE` per request, no redirects); `internal/adapters/upstream` — MCP's guarded egress, the upstream authority (protected-resource and authorization-server metadata, client-credentials tokens from `ANVILKIT_MCP_UPSTREAM_CREDENTIALS_FILE`, a token granting more than its binding's scopes refused) and the Go SDK send route.
- `internal/transport/grpc` — the listener with protovalidate, the per-method workload authorization and the error mapping; `internal/transport/identity` — the mTLS workload identity (rotating credentials, the peers' SPIFFE IDs); `internal/bootstrap` — Fx assembly, generations, the health/metrics listener, the schema version check, the `reconcile` entry point.
- `internal/testdb` — the disposable PostgreSQL 17 (Testcontainers) the tests install from the migrations.
- `deploy/chart` — the Helm chart (the service plus the owner queue relay sidecar from the background-worker image; the cert-manager workload `Certificate`, an optional HorizontalPodAutoscaler, the CSI `SecretProviderClass` under `secrets.provider: csi` and the upstream credential bindings).

## Semantics the tests prove

Domain and outbox writes commit or roll back together; an earlier allocated but later committed outbox transaction is not skipped (the adapter's xid8 watermark); a restarted subscriber resumes from its offsets. Two racing claims produce one claimant; a worker identity claims a generation once; a superseded, expired or fenced claimant's heartbeat and result are refused; an identical repeated submission returns the existing acceptance; input-digest mismatches change nothing; profile mismatches and reported failures consume the attempt within the bound; a revoked authorization cancels instead of accepting; an expired external-effect lease is released only with Control's not-sent evidence, otherwise the request is dead with `EFFECT_UNCERTAIN`. Startup failure unwinds the listeners; secret rotation replaces the pool and drains the old one; a rejected candidate leaves the active generation.
